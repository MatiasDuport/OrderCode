## Velocidad y ahorro desde el motor

El motor propio de OrderCode busca reducir tanto el tiempo de trabajo como el contexto que consume cada tarea.

| Menos espera | Menos tokens |
| :--- | :--- |
| **Índices incrementales y caché.** Reutiliza archivos ya analizados y resultados vigentes para evitar trabajo repetido. | **Contexto selectivo y compactación.** Prioriza información relevante y acota resultados extensos antes de enviarlos al modelo. |

El impacto depende de la tarea, el proyecto, el modelo y el proveedor. Estas optimizaciones actúan sobre el trabajo del motor y el contexto; la velocidad de respuesta del modelo depende también del servicio conectado.

## Empieza en tres pasos

| 01 · Abre | 02 · Conecta | 03 · Crea |
| :--- | :--- | :--- |
| Instala OrderCode y abre la carpeta de tu proyecto. | Elige tu proveedor y modelo en **Ajustes → Modelos**. | Describe tu objetivo en el chat y sigue el trabajo mientras avanza. |

Tú eliges el modelo, su nivel de esfuerzo cuando está disponible y los permisos para trabajar. La disponibilidad y los límites dependen del proveedor o plan que conectes.

## Descargas

**[Abrir instaladores oficiales →](https://github.com/MatiasDuport/OrderCode/releases/latest)**

Elige el formato y la arquitectura de tu equipo. En Releases encontrarás los paquetes que ya están publicados para cada sistema.

| Sistema | Tu equipo | Paquete |
| :--- | :--- | :--- |
| **Windows 11** | x64 | Instalador `.msi` |
| **macOS** | Apple Silicon · M1 o posterior | Imagen `.dmg` · ARM64 |
| **macOS** | Intel | Imagen `.dmg` · x64 |
| **Linux** | x64 o ARM64 | `.AppImage` o `.deb` |

¿Ya lo tienes instalado? Ve a **Ajustes → Actualizaciones**. Los paquetes del actualizador se verifican mediante firma criptográfica antes de instalarse.

<details>
<summary><strong>Instalación en macOS</strong></summary>

Abre el DMG que corresponda a tu procesador y arrastra **OrderCode** a **Aplicaciones**.

La firma y notarización de Apple requieren las credenciales de Apple Developer en el proceso de publicación. Si no están configuradas, Gatekeeper puede mostrar una advertencia. La firma del actualizador de OrderCode y la firma de Apple son mecanismos distintos.

</details>

<details>
<summary><strong>Instalación en Linux</strong></summary>

En Ubuntu o Debian puedes instalar el `.deb` con tu gestor de paquetes. Para utilizar un AppImage:

```bash
chmod +x OrderCode*.AppImage
./OrderCode*.AppImage
```

Linux requiere WebKitGTK 4.1 y las bibliotecas de escritorio de Tauri. El paquete `.deb` resuelve sus dependencias mediante el gestor de paquetes.

Para recibir actualizaciones integradas, utiliza **AppImage**. Con `.deb`, instala manualmente el paquete de la nueva versión.

</details>

## Desarrollo

Construido con **Tauri 2 · React · TypeScript · Rust · Node.js · SQLite**.

<details>
<summary><strong>Ejecutar el proyecto y crear paquetes</strong></summary>

Necesitas **Node.js 24+**, **pnpm 11**, **Rust estable** y los requisitos de compilación de Tauri 2 para tu sistema. En Linux, instala también sus dependencias de desarrollo.

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm --filter @ordercode/desktop tauri:dev
```

Para producir un paquete local, ejecuta el comando de tu sistema desde `apps/desktop`:

| Sistema | Comando |
| :--- | :--- |
| Windows | `pnpm exec tauri build --bundles msi` |
| macOS | `pnpm exec tauri build --bundles dmg` |
| Linux | `pnpm exec tauri build --bundles appimage,deb` |

La aplicación instalada incluye su runtime de Node.js. Los usuarios finales no necesitan instalar Node globalmente.

</details>

<details>
<summary><strong>Publicación y actualizaciones firmadas</strong></summary>

El [workflow de publicación](.github/workflows/release.yml) compila para Windows x64, macOS Apple Silicon, macOS Intel, Linux x64 y Linux ARM64. El release se publica cuando están presentes los paquetes y las firmas requeridas, junto con el manifiesto de actualización de cada plataforma.

Configura el secret `TAURI_SIGNING_PRIVATE_KEY` y, si corresponde, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Para la firma y notarización de Apple, configura también los secrets indicados en el workflow.

Para una nueva versión, coordina los números de versión del monorepo y la configuración del workflow antes de publicar el tag `vX.Y.Z`.

</details>
